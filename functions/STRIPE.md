# Stripe payments

One-time yearly payment per organisation code. No auto-renewal: renewals are invoiced by hand.
Pricing (see `plan.js`): first 10 users free, then $12 per user per year, capped at $199 in the first year and $399 on renewal.

## Pieces
- `createCheckoutSession` (HTTPS): the website's pay box (`assets/js/checkout.js`) sends `{ code, users }`. Add `dryRun: true` for a quote only. Returns a Stripe Checkout URL.
- `stripeWebhook` (HTTPS): Stripe calls it on `checkout.session.completed`. It raises `Codes/{code}.totalUserCount`, sets `paidUntil` (one year, extended if renewed early), and records `Payments/{sessionId}`. Each event id is processed once (`StripeEvents`).
- `payment/success.html`, `payment/cancelled.html`: where Checkout sends the buyer.

## Setup (test mode first)
Keys live in a gitignored `.secrets` file at the repo root and are pushed to Google Secret Manager by `./deploy-functions.sh`. They are never committed, never in the deployed source, and never in `functions/.env` (which `deploy.sh` compiles into the mobile app).
1. `cp .secrets.example .secrets` and fill in `STRIPE_SECRET_KEY` (`sk_test_...`). Leave `STRIPE_WEBHOOK_SECRET` as a placeholder for now.
2. `./deploy-functions.sh functions:createCheckoutSession,functions:stripeWebhook` (changed secrets are pushed first, then the functions deploy; add `DRY_RUN=1` to see the commands without running them).
3. Stripe dashboard > Developers > Webhooks > Add endpoint: `https://asia-south1-agoriya-app.cloudfunctions.net/stripeWebhook`, event `checkout.session.completed`. Copy its signing secret (`whsec_...`).
4. Put it in `STRIPE_WEBHOOK_SECRET` in `.secrets` and run `./deploy-functions.sh functions:stripeWebhook`.
5. Pay with test card `4242 4242 4242 4242` (any future date, any CVC) on the website; check the code's limit in Firestore. A test payment writes to the real Firestore: use a code you own and set `totalUserCount` back to 10 afterwards.
6. Going live: change the two values in `.secrets` to `sk_live_...` and the live-mode webhook's `whsec_...`, and run `./deploy-functions.sh functions:createCheckoutSession,functions:stripeWebhook`.

## Rules
- Self-serve is limited to 11-100 users. Above 100, `createCheckoutSession` answers with `custom: true` and the page tells the buyer to email for a custom quote; they cannot pay online.
- Refund policy: `refund/index.html` (generated by `scripts/site_pages.py`): full refund within 15 days; later, pro-rata by the day, less Stripe's processing fee. Refunds are issued by hand from the Stripe dashboard, and the code's `totalUserCount` is set back to 10 by hand.

## Run it all locally (no deploy)
Needs Java, the Firebase CLI and the Stripe CLI (`brew install stripe/stripe-cli/stripe`, then `stripe login`).
1. `functions/.secret.local` (gitignored) with your test key:
   ```
   STRIPE_SECRET_KEY=sk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...   # printed by step 3
   ```
2. Terminal 1: `cd functions && npm start` (Functions and Firestore emulators; UI at http://localhost:4000).
3. Terminal 2: `stripe listen --forward-to http://127.0.0.1:5001/agoriya-app/asia-south1/stripeWebhook`. It prints a `whsec_...`: put it in `.secret.local` and restart step 2.
4. Terminal 3, from the repo root: `python3 -m http.server 8000`, then open http://localhost:8000/#pay-box.
5. In the emulator UI (Firestore tab) add a document `Codes/ABC234` with `totalUserCount` = 10 and `currentUserCount` = 1, and use ABC234 in the pay box.
6. Pay with `4242 4242 4242 4242`. Stripe sends you back to localhost, the webhook is forwarded, and `Codes/ABC234.totalUserCount` goes up in the emulator.
The page talks to the emulator automatically when served from localhost.
